# 机器学习（站点负荷 / 占用预测）

> 细节、模型下载与 CLI 参数以 [ml/README.md](../ml/README.md) 为准。本文只讲和一期/二期怎么接。

## 它做什么

读取站点**小时快照**（parquet），用六个冻结模型预测三个目标小时（不是连续 24 点曲线）：

| 窗口 | 含义（以上午 14:00 截止为例） |
|---|---|
| H1 | `[14:00, 15:00)` 平均负荷率、充电时长占用率 |
| H6 | `[19:00, 20:00)` |
| H24 | 次日 `[13:00, 14:00)` |

模型文件约 3.4GB，**不在 git 里**，从 GitHub Releases 下载。没有模型就不能做真实推理。

## 和 Qt 怎么接

```text
用户端 / 管理端
    --TCP forecast.station / admin.forecast.station-->
admin_server（MlForecastGateway）
    --HTTP GET-->  http://127.0.0.1:5010/api/forecast/latest
                   或 /api/forecast/station/<id>
```

环境变量 `CHARGE_PILE_ML_URL` 默认 `http://127.0.0.1:5010`。客户端**不直连** 5010。

查询服务只读已发布的 JSON 批次，不在请求时训练。管理端「充电预测」页、用户端电站详情「充电预测」都走这条链路。

## 没有模型时怎么演示

仓库带模拟批次 `ml/fixtures/demo_forecast.json`（`source_kind: SIMULATED`，示例站 ID `1001`）。Ubuntu 上不要装整份 `ml/requirements.txt`（依赖对新，Ubuntu 22.04 的 Python 3.10 装不上）。查询只要 Flask：

```bash
python3 -m venv "$HOME/charging-ml-venv"
source "$HOME/charging-ml-venv/bin/activate"
pip install Flask
cd /mnt/hgfs/Small_s3/Charge_pile    # 改成实际工程根
python3 -m ml.cli.warehouse_api --store file --results-dir ml/fixtures --source-kind SIMULATED --port 5010
```

`scripts/start_all.sh` 会优先用 MEASURED 批次（`ml/fixtures/measured_forecast.json`，并绑定到 Qt 电站 ID），否则才用模拟 fixtures。

批次里没有该站 ID 时：MEASURED 查询会按电站 ID 稳定映射到同批次一条冻结模型输出；SIMULATED 仍由网关退回第一站并带 `matched: false`。

## 真预测还缺什么
