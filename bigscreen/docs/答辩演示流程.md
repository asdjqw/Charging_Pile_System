# 答辩演示流程（10 分钟版）

## 1. 先看结果（1 分钟）

打开 `http://192.168.44.129/`（或 `http://192.168.44.129:5000/`），介绍大屏：

- 顶部：9 项运营 KPI 翻牌器 + 站点类型订单占比环形图 + 充电桩日均利用率水球图
- 左列：月度充电量趋势（柱+折线）、24 小时负荷（峰/平/谷着色）、站点类型雷达、充电时长玫瑰图
- 中列：近 90 天双轴趋势、星期×小时热力图、站点 TOP10 横向条形
- 右列：工作日 vs 周末、平台对比、用户价值分层、电池健康画像
- 底栏：峰平谷漏斗、单次电量分布、行政区锥形柱、收入结构与付费率、实时订单滚动榜

一句话：**Spark 清洗与分析 → MySQL → Flask 接口 → Vue3 + DataV 大屏**，原始数据与结果同时存放在 Hadoop 3.x。

## 2. 数据与清洗（2 分钟）

```bash
cd /home/bit/charging-bigscreen && cat data/raw/nvv2t.csv | head -2   # 原始数据年份为 0014，时间字段异常
tail -20 logs/spark_yarn.log                                          # 清洗过程日志
mysql -ucharging -pcharging123 charging_screen -e "select * from ads_data_quality;"
```

讲清洗：年份修复（+2000，用 Mon~Sun 交叉验证 3395/3395 一致）、0 电量与超长时长异常订单剔除 56 条、
遥测 `record_time` 科学计数法精度丢失丢弃、电流取幅值、派生功率/压差/温升/峰平谷等指标。

## 3. Hadoop + Spark（3 分钟）

```bash
source deploy/hadoop_env.sh
jps                                             # NameNode/DataNode/ResourceManager/NodeManager
hdfs dfs -ls /user/bit/charging-bigscreen       # raw / warehouse / ads
hdfs dfs -du -h /user/bit/charging-bigscreen
yarn application -list                          # 查看 Spark on YARN 应用
```

说明：`SPARK_MASTER=yarn` 时作业提交到 YARN，数据从 HDFS 读取、结果写回 HDFS；
本机测试时同一份代码只改路径参数即可本地运行（`--raw data/raw`）。

## 4. 后端接口（1 分钟）

```bash
curl -s http://127.0.0.1/api/health
curl -s http://127.0.0.1/api/screen/bundle | head -c 300
```

讲：23 个 REST 接口、首屏聚合接口、30 秒内存缓存、MySQL 不可用时自动切 CSV 兜底。

## 6. 常见提问应答

| 提问 | 应答 |
| --- | --- |
| 为什么用 Spark 而不是直接用 SQL？ | 遥测表与订单表需要多表关联、分箱、窗口排名与 RFM 打分，Spark 便于扩展；数据量增大只需切 YARN/HDFS 路径 |
| 数据量这么小有必要用 Hadoop 吗？ | 这是课程要求的技术栈演练，同一套代码在数据量放大后无需改动，答辩环境把原始数据与结果都存放在 HDFS |
| 大屏为什么不用地图？ | 原始数据只有地址文本、无经纬度，用行政区维度做区域对比（锥形柱图）避免伪造坐标 |
| 周末数据为什么这么少？ | 数据本身周末样本仅 40 天/85 单，结论中已标注样本量，避免过度解读 |
