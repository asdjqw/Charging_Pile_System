# 答辩演示流程（约 10 分钟）

答辩使用当前正式链路：CSV → ODS TextFile → Spark SQL ORC → TXT → MySQL → Flask → Vue/DataV。所有命令均在实际部署机器的 `bigscreen/` 目录执行；页面地址使用该机器真实 IP，不背诵固定历史 IP。

## 1. 环境和服务（1 分钟）

```bash
jps
hdfs dfs -ls /warehouse/charging_pile_orc
yarn node -list                 # 单机 local Spark 时可说明不使用 YARN Executor
curl -s http://127.0.0.1:5000/api/health
```

说明：HDFS/Hive 保存离线数仓，MySQL 保存大屏查询表；Flask 只读 MySQL 并为 Vue3 大屏提供接口。

## 2. ODS 采集与四层数仓（3 分钟）

展示原始文件规模：

```bash
wc -l data/raw_expanded/*.csv
```

预期为 55,000 笔订单、24,816 条遥测、3,024 座站点（CSV 各含一行表头）。执行或展示正式入口：

```bash
LOAD_DT=2026-09-16 MODE=hdfs bash hive/scripts/load_ods.sh
bash run_etl_all.sh 2026-09-16
```

讲解：ODS 是按 `dt` 分区的 TextFile 外部表；DWD/DWS/ADS 都由 Spark SQL 处理并落地 ORC + Snappy。`run_etl_all.sh` 有 `set -euo pipefail`，日志在 `logs/etl/2026-09-16/`，失败会立即停止。

## 3. 清洗与分析口径（2 分钟）

说明 DWD 规则：

1. 修复 `0014/0015` 年份；按 `sessionId` 去重并校验关键字段。
2. 剔除电量、时长、金额异常订单；保留 0 元订单以计算支付率。
3. 订单关联站点和电池遥测，派生峰平谷、工作日/周末、平均功率、压差和温升。
4. 遥测 `record_time` 精度丢失，不伪造时间。

扩容批次的基线是 ODS 订单 55,000、DWD 有效订单 54,944。分析覆盖日/月、小时、星期×小时、站点、站型、工作日/周末、峰平谷、平台、行政区、用户、电池和收入等维度。

## 4. ORC 到 MySQL（1 分钟）

说明 ADS 是 ORC 表；Spark 将指定 `load_dt` 的 ADS 分区导出为无表头、`|` 分隔的 TXT：

```text
output/mysql_stage/2026-09-16/ads_<name>.txt
```

导入脚本检查 19 份 TXT 的文件和列数后，对每张 MySQL ADS 表执行 `TRUNCATE + LOAD DATA LOCAL INFILE`，保证同批次重跑幂等。该 TXT 是运行产物，已被 Git 忽略。

## 5. 大屏与接口（3 分钟）

打开：

```text
http://<flask-host-ip>:5000/
```

依次展示顶部 KPI、日/月趋势、小时负荷、星期×小时热力、站点 TOP、站型与工作日/周末对比、峰平谷/平台/行政区对比、用户分层、电池健康、收入和实时流水。

任选两张图验证“一图一表一接口”：

```bash
curl -s http://127.0.0.1:5000/api/charts/daily-trend | head -c 200
curl -s http://127.0.0.1:5000/api/charts/facility-compare | head -c 200
```

解释：每张图只请求一个 Flask API，API 只查询一张同名 MySQL ADS 表；不再使用旧的 `/api/screen/bundle` 或 CSV 兜底。

## 答辩表达边界

- 55,000 条订单由原始样本与北京 POI 按固定随机种子扩容，是教学模拟数据，不是实际运营全量数据。
- Hadoop/HDFS 是离线数仓；大屏实时查询源是 MySQL。
- 机器学习预测为可选加分模块，应与本次大屏数据工程链路分开说明。
