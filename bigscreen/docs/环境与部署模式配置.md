# 环境与部署模式配置

项目支持本机单机伪分布式模拟和多虚拟机集群。两种模式共用 SQL、脚本和 Python 代码，但 Hadoop/Hive 地址、MySQL 凭据和运行时配置必须分别配置，不能提交或复制某台机器生成的本地配置。

## 1. 依赖

| 类别 | 要求 | 用途 |
| --- | --- | --- |
| Python | 3.11 或 3.12 | PySpark、MySQL 导入、Flask |
| Java | 按 Hadoop/Hive 发行版要求 | Hadoop、Hive、Spark |
| Hadoop | 3.x | HDFS、YARN（集群模式） |
| Hive | 3.x 或集群统一版本 | Metastore、ODS `LOAD DATA` |
| Spark | 3.x，含 `spark-sql` | DWD/DWS/ADS 的计算引擎 |
| MySQL | 5.7/8.x | ADS 大屏查询库；也可承载 Hive Metastore |
| Node.js | 23+（答辩要求） | Vue 3 前端构建 |

```bash
cd /root/Charging_Pile_System/bigscreen
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd frontend && npm ci && npm run build
```

## 2. 配置文件边界

可以提交：`config/database.env.example`、`deploy/hadoop_env.example.sh`、HQL、脚本和文档。

以下内容仅保留本机且已被 Git 忽略：

```text
config/database.env       MySQL 主机、用户、密码
deploy/hadoop_env.sh      当前机器或当前集群的 Hadoop 地址
deploy/hive_env.sh        本机 Hive 环境变量
.runtime/                 本机 Hadoop/Hive 安装、日志、PID 与临时配置
output/                   ORC 导出 TXT、日志等可再生产物
```

```bash
cp config/database.env.example config/database.env
```

在 `config/database.env` 设置 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME=charging_screen`。正式大屏的数据源固定为 MySQL。

## 3. 单机伪分布式

单机把 NameNode、DataNode、ResourceManager、NodeManager、Hive Metastore、HiveServer2、MySQL、Spark Driver、Flask 放在一台虚拟机，适合本地开发和模拟正式链路。

```bash
cd /root/Charging_Pile_System/bigscreen
HIVE_SERVER2_PORT=10050 bash deploy/setup_hive_local.sh
source deploy/hive_env.sh
bash deploy/start_hive_local.sh

jps
hdfs dfs -ls /
beeline -u 'jdbc:hive2://127.0.0.1:10050/default' -n root -e 'SHOW DATABASES;'
```

运行数仓并导入 MySQL：

```bash
LOAD_DT=2026-09-16 MODE=hdfs SPARK_MASTER='local[2]' \
  bash deploy/run_warehouse_local.sh
```

启动大屏：

```bash
PORT=5000 .venv/bin/gunicorn -c deploy/gunicorn.conf.py backend.wsgi:application
curl http://127.0.0.1:5000/api/health
```

浏览器使用 `http://127.0.0.1:5000/`。其他设备访问时使用虚拟机实际 IP 的 5000 端口，不应使用未配置的旧 IP。

停止本机 Hive 服务：

```bash
bash deploy/stop_hive_local.sh
```

## 4. 多虚拟机集群

推荐角色：

```text
master   NameNode、ResourceManager、Hive Metastore、HiveServer2
worker1  DataNode、NodeManager、Spark Executor
worker2  DataNode、NodeManager、Spark Executor
app      MySQL、Flask、Nginx（可与 master 合并）
```

所有机器配置相同的主机名解析，例如：

```text
192.168.1.10 master
192.168.1.11 worker1
192.168.1.12 worker2
```

`core-site.xml` 的 `fs.defaultFS`、`yarn-site.xml` 的 ResourceManager、`hive-site.xml` 的 Metastore URI 都指向 `master` 或真实局域网 IP；不可写 `127.0.0.1` 或 `localhost`。工作节点应有兼容的 Python 3.11/3.12，建议同一绝对路径：

```bash
export PYSPARK_PYTHON=/opt/charging-venv/bin/python
export PYSPARK_DRIVER_PYTHON=/opt/charging-venv/bin/python
```

在已配置 Hadoop/Hive 的提交节点运行：

```bash
cd /path/to/Charging_Pile_System/bigscreen
source deploy/hadoop_env.sh
LOAD_DT=2026-09-16 MODE=hdfs SPARK_MASTER=yarn \
  bash deploy/spark_submit.sh
```

`deploy/spark_submit.sh` 执行 Hive ODS 加载与 Spark SQL ETL。MySQL 所在节点需要能访问 HDFS，以创建 `output/mysql_stage/<load_dt>/` 完成 TXT 导入。

Flask 的 `config/database.env` 填写 MySQL 所在机器地址；Flask 启动后访问：

```text
http://<flask-host-ip>:5000/
```

## 5. 端口与排查

常见端口：HDFS RPC 9000/8020（按集群配置）、NameNode UI 9870、YARN UI 8088、Hive Metastore 9083、HiveServer2 10000 或实际配置端口、MySQL 3306、Flask 5000。

```bash
hdfs dfsadmin -report
yarn node -list
hive -e 'SHOW DATABASES;'
curl http://127.0.0.1:5000/api/health
```

- NameNode 只能在主节点启动；每台机器各启一个 NameNode 会形成互不相通的 HDFS。
- `LOAD DATA INPATH` 会移动 HDFS staging 文件；下次运行脚本会重新上传。
- Spark/Hive 查不到同一批表时，检查 `hive-site.xml` 和 Metastore URI 是否一致。
- MySQL 导入失败时，确认服务端和客户端允许 `LOCAL INFILE`，并检查 `output/mysql_stage/<load_dt>/` 的 ETL 日志。
