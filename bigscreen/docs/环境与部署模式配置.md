# 环境与部署模式配置

本文统一说明充电桩大屏项目的运行环境，以及“单机伪分布式”和“多虚拟机集群”两种部署方式。两种方式共用代码、HQL 和 Python 依赖，但 Hadoop/Hive 的地址配置不同，不能混用本机生成的配置文件。

## 1. 两种模式的边界

```text
单机伪分布式：一台虚拟机
  NameNode + DataNode + ResourceManager + NodeManager
  Hive Metastore + HiveServer2 + MySQL + Spark Driver + Flask

多虚拟机集群：主节点 + 工作节点
  主节点：NameNode、ResourceManager、Hive Metastore、HiveServer2
  工作节点：DataNode、NodeManager、Spark Executor
  应用节点：MySQL、Flask、Nginx（可与主节点合并）
```

项目有两条兼容链路：

| 链路 | 作用 | 单机运行 | 多机运行 |
| --- | --- | --- | --- |
| Spark → MySQL | 现有大屏快速试运行 | 本地 Spark 或本机 YARN | Spark on YARN |
| Hive 四层数仓 | ODS → DWD → DWS → ADS 标准数仓 | 本机 HDFS/Hive | 集群 HDFS/Hive |

单机脚本只负责本机模拟；集群答辩应使用集群管理员提供的 Hadoop/Hive 配置，不要在每台机器执行本机启动脚本。

## 2. 环境依赖

### 2.1 Python 与 Python 包

- Python 3.11 或 3.12，本项目当前使用 Python 3.12。
- PySpark 3.5.3
- Flask 3.0.3、flask-cors 4.0.1、PyMySQL 1.1.1
- pandas 2.2.3
- Linux 使用 gunicorn；Windows 可使用 waitress。

安装 Python 环境：

```bash
cd /root/Charging_Pile_System/bigscreen
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

### 2.2 系统组件

| 组件 | 建议版本 | 用途 |
| --- | --- | --- |
| Java | OpenJDK 17 | Hadoop 3.5 服务端、YARN |
| Java | OpenJDK 8u371+ | 本机 Hive 3.1.3/HiveServer2 |
| Java | OpenJDK 11/17 | 普通 Spark 调试可用 |
| Hadoop | 3.x | HDFS 存储、YARN 计算 |
| Hive | 3.1.3 或集群统一版本 | Hive Metastore、四层数仓 |
| MySQL | 5.7/8.x | Flask 查询库、Hive Metastore 库 |
| Node.js | 23 及以上 | Vue3 前端构建 |

Python 依赖记录在 [`requirements.txt`](../requirements.txt)，前端依赖记录在 [`frontend/package-lock.json`](../frontend/package-lock.json)。Java、Hadoop、Hive、MySQL 不属于 pip 依赖。

## 4. 单机伪分布式配置

### 4.1 地址约定

本机模式所有服务在同一台机器：

```text
HDFS              hdfs://127.0.0.1:9000
NameNode UI       http://127.0.0.1:9870
YARN UI           http://127.0.0.1:8088
Hive Metastore    thrift://127.0.0.1:9083
HiveServer2       jdbc:hive2://127.0.0.1:10050/default
MySQL             127.0.0.1:3306
Flask             0.0.0.0:5000
```

`10050` 是当前机器实际使用的 HiveServer2 端口；如果端口空闲，可以改回 `10000`。

### 4.2 安装与启动

```bash
cd /root/Charging_Pile_System/bigscreen

# 已安装 Java 8/11/17、Hadoop 服务端和 MySQL 后执行
HIVE_SERVER2_PORT=10050 bash deploy/setup_hive_local.sh
source deploy/hive_env.sh
bash deploy/start_hive_local.sh
```

验证：

```bash
hdfs dfs -ls /
beeline -u 'jdbc:hive2://127.0.0.1:10050/default' -n root -e 'SHOW DATABASES;'
jps
```

### 4.3 运行 Hive 四层数仓

使用 `MODE=hdfs` 可以模拟“上传到 HDFS staging 后由 Hive LOAD 采集”的正式链路：

```bash
source deploy/hive_env.sh
LOAD_DT=2026-09-15 \
MODE=hdfs \
LOCAL_RAW="$PWD/data/raw_expanded" \
WAREHOUSE_ROOT=/warehouse/charging_pile \
SPARK_MASTER='local[2]' \
SPARK_SUBMIT="$PWD/.venv/bin/spark-submit" \
ANALYTICS_SQL_CMD="$PWD/.venv/bin/spark-sql --master local[2]" \
bash hive/scripts/build_warehouse.sh
```

这里的 Spark 计算使用本机执行器，HDFS、Hive 外部表、Metastore、分区和 `LOAD DATA INPATH` 仍是正式链路形态。单机使用 Spark SQL 构建 DWS/ADS，可以避免 YARN 为每张小汇总表重复启动应用。

停止服务：

```bash
bash deploy/stop_hive_local.sh
```

### 4.4 运行现有 Spark/MySQL 大屏链路

```bash
.venv/bin/python spark/jobs/run_all.py --raw data/raw_expanded
.venv/bin/python spark/jobs/load_mysql.py
PORT=5000 .venv/bin/python -m backend.wsgi
```

浏览器访问 `http://127.0.0.1:5000/`。

## 5. 多虚拟机集群配置

以下以三台机器为例：

```text
master   192.168.1.10
worker1  192.168.1.11
worker2  192.168.1.12
```

实际项目已有 `bitdev`/局域网 IP 部署记录时，以集群实际主机名和 IP 为准。

### 5.1 主机名解析

所有机器的 `/etc/hosts` 都加入：

```text
192.168.1.10 master
192.168.1.11 worker1
192.168.1.12 worker2
```

确保每台机器都能执行：

```bash
ping master
ssh worker1 hostname
```

### 5.2 Hadoop 角色与核心配置

主节点运行 NameNode、ResourceManager；工作节点运行 DataNode、NodeManager。

所有节点使用统一的 Hadoop 配置：

`core-site.xml`：

```xml
<property>
  <name>fs.defaultFS</name>
  <value>hdfs://master:9000</value>
</property>
```

`hdfs-site.xml`：

```xml
<property>
  <name>dfs.replication</name>
  <value>2</value>
</property>
<property>
  <name>dfs.namenode.http-address</name>
  <value>master:9870</value>
</property>
```

`yarn-site.xml`：

```xml
<property>
  <name>yarn.resourcemanager.hostname</name>
  <value>master</value>
</property>
<property>
  <name>yarn.nodemanager.aux-services</name>
  <value>mapreduce_shuffle</value>
</property>
```

`workers` 文件：

```text
worker1
worker2
```

不要在多机环境使用 `fs.defaultFS=hdfs://localhost:9000`；`localhost` 会指向当前节点，而不是 NameNode。

### 5.3 Hive Metastore 与 MySQL

建议 Metastore 和 HiveServer2 只部署在 `master`。所有 Hive 客户端的 `hive-site.xml` 指向同一个 Metastore：

```xml
<property>
  <name>hive.metastore.uris</name>
  <value>thrift://master:9083</value>
</property>
<property>
  <name>hive.metastore.warehouse.dir</name>
  <value>/warehouse/tablespace/managed/hive</value>
</property>
<property>
  <name>javax.jdo.option.ConnectionURL</name>
  <value>jdbc:mysql://192.168.1.10:3306/hive_metastore?useSSL=false</value>
</property>
```

MySQL 用户需要允许 Metastore 主机连接；生产环境应限制为实际主机网段，不建议使用 `%` 的宽泛授权。

主节点启动：

```bash
hive --service metastore
hive --service hiveserver2
```

集群客户端连接：

```bash
beeline -u 'jdbc:hive2://master:10000/default'
```

### 5.4 Spark on YARN

所有 Spark 工作节点必须具备兼容的 Python 3.11/3.12 和 PySpark 版本。路径可以统一为 `/opt/charging-venv/bin/python`，或者使用集群统一 Python 分发方案。

```bash
source deploy/hadoop_env.sh
export SPARK_MASTER=yarn
export PYSPARK_PYTHON=/opt/charging-venv/bin/python
export PYSPARK_DRIVER_PYTHON=/opt/charging-venv/bin/python
```

运行四层 Hive 数仓：

```bash
LOAD_DT=2026-09-15 \
MODE=hdfs \
LOCAL_RAW="$PWD/data/raw_expanded" \
WAREHOUSE_ROOT=/warehouse/charging_pile \
SPARK_MASTER=yarn \
SPARK_SUBMIT=spark-submit \
HIVE_CMD=hive \
bash hive/scripts/build_warehouse.sh
```

也可以使用 HiveServer2：

```bash
HIVE_CMD='beeline -u jdbc:hive2://master:10000/default' \
SPARK_MASTER=yarn \
MODE=hdfs \
bash hive/scripts/build_warehouse.sh
```

### 5.5 Flask、MySQL 和前端

Flask 所在节点应监听 `0.0.0.0`，MySQL 地址写入该节点的 `config/database.env`：

```env
DB_HOST=192.168.1.10
DB_PORT=3306
DB_NAME=charging_screen
```

启动：

```bash
PORT=5000 .venv/bin/gunicorn -c deploy/gunicorn.conf.py backend.wsgi:application
```

浏览器访问：

```text
http://192.168.1.10:5000/
```

Nginx 与 Flask 在同一台机器时，`proxy_pass http://127.0.0.1:5000` 可以保留；如果 Nginx 在其他机器，应改成 Flask 节点的局域网 IP。

## 6. 防火墙与端口

多机部署至少需要按角色放行：

```text
9000   NameNode RPC
9870   NameNode Web UI
8032   ResourceManager RPC
8088   YARN Web UI
9083   Hive Metastore
10000  HiveServer2（或实际配置端口）
9866   DataNode 数据传输
8042   NodeManager
3306   MySQL
5000   Flask
```

### 6.1 常见冲突

- 每台机器都启动 NameNode：会形成多个独立 HDFS，数据不会自动合并。
- 使用 `127.0.0.1` 作为 Metastore/HDFS 地址：其他节点无法访问。
- 把本机 `.runtime/hadoop-conf` 复制到集群：会把集群指向错误的本机地址。
- 工作节点没有相同 Python 路径：Spark Executor 会启动失败。
- HiveServer2 与其他程序端口冲突：修改 `hive.server2.thrift.port`，并同步 Beeline、Flask 或文档中的连接地址。
- Hadoop 3.5 服务端与 Hive 3 客户端 Java 版本混用：单机脚本已分别处理；集群应按管理员统一的 Hadoop/Hive/Java 版本部署。

```bash

```
