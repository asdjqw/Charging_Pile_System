# 答辩要点（数据清洗 + 多维分析 + 大屏）

## 一、一句话介绍

对充电桩订单、电池遥测、充电站三张原始表做 Spark 清洗与 15 个维度的统计分析，
结果落 MySQL，Flask 提供接口，Vue3 + DataV 大屏展示，支持 HDFS 存储与 Spark on YARN 运行。

## 二、数据清洗做了什么（可讲"为什么"）

1. **发现并修复年份异常**：`created` 为 `0014-11-18`，第一时间会以为是脏数据；
   通过 `Mon~Sun` 独热列与日期星期比对（修正后 3395/3395 一致）确认实际年份是 2014，统一 +2000 修复。
2. **异常订单识别**：55 条电量为 0 的记录（无效充电）、1 条 55.2 小时的超长记录等，
   共剔除 56 条（占 1.65%），并保留剔除原因供质量面板展示。
3. **无效字段剔除**：遥测表 `record_time` 全部是 `2.02E+13` 的科学计数法，有效数字丢失、无法还原真实时间，直接丢弃并说明原因。
4. **业务口径统一**：充电电流原始为负（方向约定）统一取幅值；金额/电量/时长转 double；
   派生平均功率、单价、单体压差、温升、SOC 分箱等分析指标。
5. **多表关联**：遥测 `esd` = 订单 `sessionId` 关联率 98.8%（1575/1594），再从站名解析行政区、道路、站点类型。

## 三、分析维度与对比分析

- **15 个分析维度**：KPI 总览、日/月趋势、24 小时负荷、星期×小时热度、站点排行、行政区分布、
  站点类型对比、工作日 vs 周末、峰平谷对比、用户 RFM 分层、时长分布、电量分布、功率分布、
  电池健康、收入结构与平台对比。
- **5 组对比分析**：站点类型对比、工作日 vs 周末、峰平谷时段对比、平台对比、行政区对比。

## 四、可直接口述的结论

| 结论 | 数据支撑 |
| --- | --- |
| 用户价值高度集中 | 30 名高价值用户（35.7%）贡献 80.4% 充电量 |
| 交直流站是主力 | 交直流站电量占比 54.3%、订单占比 53.9% |
| 超充站商业价值最高 | 付费率 38.68%，交流站仅 3.57% |
| 周末充电需求明显偏低 | 工作日日均 16.6 单/97.66 kWh，周末日均 2.13 单/14.45 kWh |
| 谷电利用率低 | 谷段订单仅 0.51%，峰段 41.54%，具备错峰引导空间 |
| 电池一致性随 SOC 下降 | 单体压差 20% 时 13.4mV → 80% 时 29.0mV |
| 区域集中度高 | 经开区 + 二七区 + 航空港区占电量 57.9% |

## 五、技术亮点

1. 清洗与分析全部在 Spark 中完成，输出 parquet + 单文件 CSV，**本地与 HDFS 路径仅差一个参数**。
2. 结果表自动建库装载 MySQL（`load_mysql.py` 自动推断列类型、建索引），后端加 30s TTL 缓存，
   大屏 60s 自动刷新，首屏聚合接口 `/api/screen/bundle` 一次请求返回 19 个数据集。
3. 后端提供 **CSV 兜底数据源**：MySQL 不可用时自动切换，保证答辩现场大屏不"开天窗"。
4. 大屏使用 DataV（边框盒、装饰、滚动榜、锥形柱图、环形图、水球图）配合 ECharts
   16 类图表（柱、折线、面积、双轴、雷达、热力、玫瑰、漏斗、散点等），1920×1080 设计、等比自适应缩放。
5. 全链路一键脚本：`deploy/deploy.sh`（部署）、`deploy/run_pipeline.sh`（重跑计算）、`deploy/spark_submit.sh`（HDFS+YARN）。
