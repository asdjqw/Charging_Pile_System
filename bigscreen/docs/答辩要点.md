# 答辩要点（分析大屏）

## 一句话

项目将订单、遥测、站点三张 CSV 经 Hive ODS TextFile 采集，再用 Spark SQL 建设 DWD/DWS/ADS 四层数仓；DWD、DWS、ADS 统一为 ORC + Snappy。ADS 按图表一一导入 MySQL，Flask 提供接口，Vue3 + DataV + ECharts 展示。

## 数据工程亮点

1. ODS 按 `dt` 分区保存贴源 TextFile，使用 Hive `LOAD DATA`；原始 CSV 不被改写。
2. DWD 修复 `0014/0015` 年份，按 `sessionId` 去重，清理电量/时长/金额异常，保留 0 元订单；遥测时间精度不可恢复时不伪造。
3. DWD 关联订单、站点、遥测，派生行政区、峰平谷、工作日/周末、平均功率、电芯压差和温升。
4. DWD/DWS/ADS 都由 Spark SQL 写入 ORC + Snappy；ODS 是唯一 TextFile 原始层。
5. `run_etl_all.sh` 使用 `set -euo pipefail`，按 DWD → DWS → ADS → TXT → MySQL 记录日志并失败即停。
6. ADS ORC 先转无表头管道符 TXT，再以 `TRUNCATE + LOAD DATA LOCAL INFILE` 幂等写入 MySQL。

## 分析与大屏

大屏包含日/月趋势、小时负荷、星期×小时热力、站点排行、站型、工作日/周末、峰平谷、平台、行政区、时长/电量分布、用户分层、电池健康、收入和实时订单等维度，包含多组对比分析。

16 张图表均为“一图一表一接口”：一张 ECharts/DataV 图调用一个 Flask API，API 读取一张同名 MySQL ADS 表。顶部总览、质量、链路状态使用 3 张辅助 ADS 表。旧 CSV 兜底和 `/api/screen/bundle` 不再用于正式链路。

## 可讲数字

- 扩容输入：55,000 笔订单、24,816 条遥测、3,024 座北京站点。
- DWD 有效订单：54,944；异常订单：56。
- 这些是固定随机种子生成的教学模拟数据，不应表述为真实运营全量数据。

## 演示入口

```bash
LOAD_DT=2026-09-16 MODE=hdfs bash hive/scripts/load_ods.sh
bash run_etl_all.sh 2026-09-16
curl -s http://127.0.0.1:5000/api/health
curl -s http://127.0.0.1:5000/api/charts/daily-trend | head -c 200
```

浏览器访问 `http://<flask-host-ip>:5000/`。大屏查询源是 MySQL；HDFS/Hive 是离线数仓与 ETL 存储层。
