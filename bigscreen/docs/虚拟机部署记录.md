### 关键注意点（踩坑记录）

1. **HDFS 地址必须用 `bitdev:9000`，不能用 `localhost:9000`**：
   虚拟机上 `127.0.0.1:9000` 被另一个服务（`admin_server` 进程）占用，
   连 `localhost:9000` 会得到 `EOFException`，看起来像 Hadoop 版本不兼容，实际是连错了服务。
   `core-site.xml` 里 `fs.defaultFS = hdfs://bitdev:9000`，因此建议直接使用不带前缀的 HDFS 路径。
2. **Hadoop 环境变量未写入 `.bashrc`**：非交互 SSH 会话里 `hadoop/hdfs/yarn` 不在 PATH，
   部署时已生成 `deploy/hadoop_env.sh`，执行前 `source` 即可。
3. **Spark 用 Java 11，Hadoop 用 Java 8**：虚拟机自带 JDK 1.8.0_261 运行 Hadoop 3.2.1；
   Spark 3.5.3 官方要求 Java 8u371+/11/17，因此部署时额外安装 `openjdk-11-jdk-headless` 供 Spark 使用。
4. **HDFS 结果目录结构**：Spark 写 HDFS 时每张表是一个目录（`<表名>.parquet`、`<表名>.csv_dir`），
   `deploy/fetch_from_hdfs.sh` 使用 `hdfs dfs -getmerge` 合并为单文件 CSV 后再装载 MySQL。

## 八、补充踩坑

1. **同步代码时不要覆盖 `config/database.env`**：本地用的是 `root/空密码`，虚拟机上应用账号是 `charging/charging123`；
   覆盖后会出现 `Access denied for user 'root'@'localhost'`，按本文件第五节重新写入即可。
2. **对方服务的 TCP 端口 9000 与 Hadoop NameNode 冲突**：对方默认 `CHARGE_PILE_PORT=9000`，
   而本机 Hadoop 的 NameNode RPC 也占用 9000，因此重启对方服务时改为 `CHARGE_PILE_PORT=9100`
   （同时用 `CHARGE_PILE_WEB_ROOT` 指向替换后的大屏目录、`CHARGE_PILE_BIND_ADDRESS=0.0.0.0` 允许外部访问）。
