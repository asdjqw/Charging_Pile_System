# 虚拟机部署记录与交接模板

本文件不记录已失效的固定 IP、用户名或历史服务名。每次在新虚拟机或多机集群部署时，按下表填写实际信息，避免把单机配置误用于集群。

## 1. 当前环境登记

| 项 | 实际值（部署时填写） |
| --- | --- |
| 工程目录 | `/root/Charging_Pile_System/bigscreen` 或实际路径 |
| Python | `python3 --version` |
| Node.js | `node --version`（答辩要求 23+） |
| Hadoop / HDFS URI | `hdfs getconf -confKey fs.defaultFS` |
| Hive Metastore | 实际 thrift URI |
| Spark Master | `local[2]` 或 `yarn` |
| MySQL | 主机、端口、数据库 `charging_screen` |
| Flask | `http://<实际IP>:5000/` |
| 数仓根目录 | `/warehouse/charging_pile_orc` 或实际 `WAREHOUSE_ROOT` |

不得提交本机文件：`config/database.env`、`deploy/hadoop_env.sh`、`deploy/hive_env.sh`、`.runtime/`、`output/`。

## 2. 单机伪分布式

```bash
cd /root/Charging_Pile_System/bigscreen
HIVE_SERVER2_PORT=10050 bash deploy/setup_hive_local.sh
source deploy/hive_env.sh
bash deploy/start_hive_local.sh

jps
hdfs dfs -ls /
beeline -u 'jdbc:hive2://127.0.0.1:10050/default' -n root -e 'SHOW DATABASES;'

LOAD_DT=2026-09-16 MODE=hdfs SPARK_MASTER='local[2]' \
  bash deploy/run_warehouse_local.sh
```

## 3. 多虚拟机集群

推荐主节点运行 NameNode、ResourceManager、Hive Metastore、HiveServer2；工作节点运行 DataNode、NodeManager 和 Spark Executor；应用节点运行 MySQL、Flask（可合并到主节点）。

所有节点必须使用主机名或局域网 IP 配置 `fs.defaultFS`、ResourceManager 和 Hive Metastore，不能使用 `localhost`；并提供兼容 Java/Hadoop/Spark 版本和相同的 Python 3.11/3.12 路径。

提交节点运行：

```bash
cd /path/to/Charging_Pile_System/bigscreen
source deploy/hadoop_env.sh
export PYSPARK_PYTHON=/opt/charging-venv/bin/python
export PYSPARK_DRIVER_PYTHON=/opt/charging-venv/bin/python
LOAD_DT=2026-09-16 MODE=hdfs SPARK_MASTER=yarn \
  bash deploy/spark_submit.sh
```

MySQL 所在节点需要有 HDFS 客户端，用于将 ADS ORC 导出为本地 TXT 后执行幂等导入。

## 4. 大屏服务

```bash
cp config/database.env.example config/database.env
# 填写真实 MySQL 地址与凭据
PORT=5000 .venv/bin/gunicorn -c deploy/gunicorn.conf.py backend.wsgi:application
curl http://127.0.0.1:5000/api/health
```

局域网访问使用 `http://<flask-host-ip>:5000/`。若前置 Nginx，`proxy_pass` 指向 Flask 所在主机；Nginx 不是本项目正式链路的必需组件。

## 5. 运行后核对

```bash
hdfs dfs -ls /warehouse/charging_pile_orc
mysql -e 'USE charging_screen; SHOW TABLES LIKE "ads_%";'
curl -s http://127.0.0.1:5000/api/charts/daily-trend | head -c 200
```

接口没有数据时，按 ODS → DWD → DWS → ADS → `output/mysql_stage` → MySQL 的顺序检查 `logs/etl/<load_dt>/`；不要恢复已移除的旧 CSV 分析脚本。
